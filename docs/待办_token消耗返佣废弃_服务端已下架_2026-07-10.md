## 一句话结论

**「token 消耗返佣」（`token_usage` / `token_usage_settled` / `token_commission_cents`）是 2026-07-03 旧设计的纸面残留，业务上从未真正存在、现已停用。** 客户端合同与代码里还留着它，需要清理。

## 为什么废弃（背景）

- 胖虎AI**中转站**（newapi）从来**没有**"按 token 用量结算的返佣"——经对中转站现行源码只读核查确认：中转站只有**「邀请下游充值返佣」**（被邀请人充值时给邀请人返佣），没有任何按用量的返佣。
- 服务端后台 panghu-admin 的佣金引擎里，`token_usage` **从来没有任何事件源去触发**（`record_commission_event` 只被付费激活/工具订单/装机调用），却因早期 seed 默认写了 10/5/3/2/1 并启用，长期在后台佣金规则页挂着一条"启用中的假返佣"，误导运营。属于 2026-07-03 合同 §18 定的四类事件里唯一对不上真实业务的一类。

## 服务端（panghu-admin）已经做了什么（2026-07-10）

- `seed_default_rules` 不再给 `token_usage` 写默认费率（改为全 0）。
- 后台佣金规则页**隐藏** token 消耗返佣（表格行 + 新增覆盖下拉都不再出现）。
- README / 代码注释去掉 10/5/3/2/1 宣传，标注"已停用（历史遗留）"。
- **刻意保留了兼容**：`CommissionEventType.TOKEN_USAGE` 枚举、代理中心快照的 `token_commission_cents` 字段（恒 0）、`commission_events` 事件类型都**没删**——就是为了不单方面破坏客户端合同和历史账本，等客户端这边改完再协同彻底移除。
- 详见共享 hub `PANGHUAI_CHANGE_LOG.md` 2026-07-10「佣金对齐：token 消耗返佣下架」条目。
- 真实在用的返佣是**「邀请下游充值返佣」**，发生在中转站（数据在 newapi 库 `users.aff_history`）；后台作为总控后续会只读聚合它（用户要求先不接线上、等本地中转站重构完再接）。
