# 开源对标功能补足方案

日期：2026-07-03　状态：方案待用户批准，未改代码
对标项目：cc-switch（farion1231，Tauri 桌面版，同时管 Claude Code/Codex/Gemini CLI/OpenClaw/Hermes/OpenCode）、Codex++（BigPizzaV3，Codex App 增强启动器）、CCR（claude-code-router，本地路由网关）

## 0. 先说一个重要前提

这三个工具在我们客户端里目前被列为**风险插件**（检测到就阻断部署）——因为它们的核心用途是"随意切换供应商"，会把买家从胖虎AI网关切走，破坏商业模型。所以本方案的原则是：**借它们的工程机制（切换/备份/测速/统计的做法），不借它们的商业方向（多供应商自由切换）**。所有补足功能都必须让买家"在胖虎AI体系内用得更爽"，而不是"更容易离开"。风险插件检测照旧保留。

## 2. 采纳项详细设计（P0 三项）

### 2.1 配置快照管理器（对标 cc-switch Profile 机制）

现状：Codex 已有 `~/.codex/panghu_modes/` 模式快照；其他四个 Agent 只有"写入前备份一次"，无管理、无界面。

方案：统一快照层 `panghu_config_snapshots/`（每 Agent 一个目录），机制照搬 cc-switch 的做法：
- 每次配置写入前自动快照（带时间戳+触发原因），保留最近 N 份（默认 10，可配）。
- 原子切换：先写临时文件 → 校验（复用现有 openclaw validate / hermes check / 结构校验）→ rename 覆盖，失败自动回滚，杜绝写一半。
- UI：配置Agent 模块加"配置历史"面板，列出快照，一键回滚任意一份，回滚也先做快照（可反悔）。
- Codex 三模式快照并入该统一层，消除两套机制。

### 2.2 一键恢复（对标 Codex++ 的官方登录切回）

- 每个 Agent 加"恢复官方初始配置"按钮：清除胖虎AI网关配置，恢复接管前的原始快照（首次接管时自动留存的 `original` 快照）；Codex 即现有"官方直登"能力的推广。
- 交付回收场景：客服/退款流程可指引客户一键恢复，配合服务端"只补次数"退款政策。
- 恢复操作写入 Execution Trace Log，客服可追踪。

### 2.3 配置完整性巡检（对标 cc-switch 漂移检测 + 现有风险插件检测融合）

- 启动时和配置页进入时，比对当前各 Agent 配置与最后一次胖虎写入的期望值（base_url、key 指纹、模型）。
- 漂移分级：网关地址被改（红，影响计费）→ 提示一键修复；模型被改（黄）→ 提示；无关字段（灰）→ 忽略。
- 与风险插件检测联动：检测到 ccswitch/codex++ 本体时照旧阻断，同时报告它们造成的配置漂移。

## 3. P1 两项要点

**用量面板**：中转站（newapi 系）自带用量/余额 API（`/api/user/self`、日志接口）。客户端在"胖虎AI网站"模块加"用量"页：余额、今日/本月 token 消耗、按模型分布、最近请求日志（脱敏）。只读展示，数据全部来自服务端，符合"不本地记账"边界。需要中转站确认对外开放哪些统计接口（服务端配合项）。

**线路测速**：对网关候选线路（主域名 + 未来备用域名）定期 HEAD/小请求测延迟，展示在配置页；多线路上线后支持"自动选最快"，写配置时选当前最优线路。熔断/failover 的完整形态需要中转站提供备用域名后才有意义（服务端配合项）。

## 4. 实施顺序与工作量估计

| 阶段 | 内容 | 预估 |
| --- | --- | --- |
| 第一批 | 2.1 快照管理器 + 2.2 一键恢复（同一套底层） | 2-3 个工作轮 |
| 第二批 | 2.3 配置巡检 | 1-2 轮 |
| 第三批 | 用量面板（需中转站接口确认） | 1-2 轮 |
| 第四批 | 线路测速；MCP 管理、提示词模板、配置导入（P2） | 按需 |

每批交付都带：单元测试 + 现有验收脚本回归 + UI 截图复核；快照/恢复功能必须有"回滚的回滚"测试。

## 5. 用户决策（2026-07-03 已确认）

1. 优先级排序：按本方案 P0→P2 执行（用户授权 Claude 决定）。
2. 中转站待办 ✅：向客户端开放用量统计接口（余额/消耗/按模型分布/请求日志），已记入 INTEGRATION.md 集成待办。
3. MCP 统一管理 ✅：基础能力免费 + 高级部分可作增值业务，免费/收费边界由管理员后台开关控制（复用 value_added_services 目录：新增 `mcp_management` 服务条目，status 和定价服务端可配）。
4. 快照保留份数 ✅：默认 10 份（original 初始快照永不清理，不占名额）。
