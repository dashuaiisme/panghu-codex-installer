## 0. 待用户确认的架构落点（开工前唯一阻塞项）

服务端代码放在哪里，二选一：

- **方案 A（推荐）**：新建独立项目"胖虎AI后台管理系统"，独立仓库、独立部署，通过内部 API 与中转站（newapi 网关）对接用户/额度/订单数据。职责干净，不污染网关。
- **方案 B**：直接扩展胖虎AI中转站仓库，在网关内加代理业务模块。省一次部署，但网关与业务后台耦合，升级 newapi 上游时冲突风险大。

## 1. 交付物一：代理业务管理后台

管理员一级菜单"代理业务管理"，覆盖合同 §10/§11/§12/§18 全部能力。

数据表（合同 §18 已定义骨架）：`agent_products`、`agent_applications`、`agent_relations`、`commission_rules`、`commission_ledger`、`settlement_requests`、`agent_marketing_content`。

管理端功能与默认值（全部可视化可改）：

| 功能 | 默认值（用户已决策） |
| --- | --- |
| 五级产品设置（价格/有效期/审核/隐藏） | L1 免费自动开通；L2-L3 收费自动；L4-L5 收费+审核；年费制；金额上线前填写 |
| token 返佣比例（按层） | 10% / 5% / 3% / 2% / 1% |
| 激活返佣（按订单金额百分比，按层） | 默认 0，上线前必须配置（后台强校验未配置不允许启用代理业务） |
| 安装返佣（按层） | 同上，默认 0 |
| 佣金互斥 | 同一 `source_event_id` 只触发一种佣金事件，硬约束 |
| 单代理覆盖 | 全局规则 + 按代理 ID 覆盖表 |
| 结算周期 | T+30（pending → available） |
| 提现 | 最低 500 元、仅支付宝、全部人工审核（审核人、放款流水、失败原因留痕） |
| 归因 | 邀请码 + 专属链接双通道；注册时绑定，永久不可更换（无解绑接口，仅人工特批工单） |
| 风控 | 人工判定；账本冻结/解冻/冲正操作 + 操作日志 |
| 招商页内容管理 | `agent_marketing_content` 管理 `/agent/join`；初稿见 `docs/代理招商页文案草稿.md` |

对外 API（合同 §18）：`GET /api/agent/public/offering`、`POST /api/agent/applications`、`GET /api/agent/center`、`GET /api/agent/customers`、`GET /api/agent/ledger`、`POST /api/agent/settlements` + 管理端 CRUD。响应字段必须符合客户端 `commercial_api.py` 已实现的请求构造与快照白名单（`agent_center` 摘要七字段：downstream_count、token/activation/agent_install_commission_cents、available/pending/frozen_cents）。

## 2. 交付物二：连接通讯软件服务端

平台范围（用户已决策）：微信、飞书、企业微信，三个都做；建议实现顺序：企业微信 → 飞书 → 微信（按官方 API 开放程度排序，微信个人号无官方 bot API，需明确用企业微信客服/公众号通道替代，个人微信机器人有封号风险——此点需用户知悉）。

按合同 §16 实现：独立服务商品（定价后台可设置）、独立订单、独立配置会话、平台通道管理、入站消息记录、Agent Runtime Adapter 调用、出站回复记录、唯一 `source_event_id` 幂等、验收记录、防断网/禁Key/取消授权卡扣费状态机。客户端侧订单/会话/测试/预检链路已实现（R3/R5），服务端按同一字段合同对接。

## 3. 交付物三：value_added_services 服务目录接口

按 `INTEGRATION.md` §4 合同实现：服务端下发统一目录（gpt_plus、phone_card、sms_code、communication_software_link、agent_center），含 status/entry_url/summary_url/safe_display_fields/unverified_reason；手机接码与 Plus 订阅初始 status=`pending_production`（客户端显示"待接入"）。目录纳入商业 manifest 签名。

## 4. 支付（端内支付，支付宝）

架构决定：**端内支付 = 客户端内置 WebView 打开服务端支付宝收银台页面完成支付**，不引入桌面端原生支付 SDK，不改变"桌面端不本地处理支付回调"的安全边界。服务端提供：创建订单 → 返回支付页 URL → 客户端 WebView 打开 → 支付宝回调服务端 → 服务端写权益/佣金账本 → 客户端轮询 `payment-status`（客户端轮询接口已实现）。

退款政策：只补次数——交付失败不退现金，补配置次数；佣金账本不做现金冲正，只在权益表调整次数（合同 §12 的冲正逻辑相应简化为"补次数事件"，需在合同文档同步一节）。

## 5. 客服

微信群为唯一客服通道：客户端诊断包导出（已实现脱敏）引导文案改为"发送至客服微信群"；服务端 support_actions 字段返回微信群二维码页 URL。

## 6. 验收门（做好才算好）

1. 后台每个配置项改动 → 客户端快照/招商页实时生效。
2. 全链路演练：注册（带邀请码）→ 充值 → 触发三类佣金 → T+30 转 available → 提现审核 → 支付宝打款留痕。
3. 佣金互斥、五级层深（receiver.level >= depth）、退款补次数、冻结/冲正全部有自动化测试。
4. 通讯软件三平台各完成一次真实入站→Agent→出站闭环验收。
5. 客户端 `commercial_release_acceptance` 相关 WARN 项不因服务端上线而回归。
