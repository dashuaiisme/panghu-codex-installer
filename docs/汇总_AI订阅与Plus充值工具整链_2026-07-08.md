> 目的：把两个项目——**胖虎AI（客户端 + panghu-admin 后台）** 与 **Plus充值工具（`codex/Plus session.脚本工具`）**——汇总成一条交付链，明确"谁做什么、怎么接、怎么一起上线"。

## 0. 一句话

买家在胖虎AI客户端「增值业务 → AI订阅服务」买 GPT Plus 代充 → 支付宝付款 → 胖虎AI服务端发一张一次性卡密并写入 Plus 工具的卡密库存 → 客户端内置浏览器带 `?code=卡密` 打开 Plus 工具 → 买家输卡密+自己的 ChatGPT session → 工具自动升级 Plus、关续费、换卡删卡 → 核销卡密。全链无需买家账号密码，卡密一次性防刷。

## 2. 卡密契约（两边共同锚点，权威）

Plus工具 `INTEGRATION.md §3` 定义，licenseServer.js 已实现，胖虎侧 `subscription_cards.py` 已按此对接：

| 用途 | 端点 | 调用方 | 令牌 |
|---|---|---|---|
| 写卡密入库存（付款成功后） | `POST /api/admin/activation-codes/import`，体 `{codes, product:"chatgpt_plus", status:"issued"}` | panghu-admin | `LICENSE_ADMIN_TOKEN`（Bearer） |
| 校验并锁定卡密 | `POST /api/activation-codes/redeem` | Plus工具 | `LICENSE_SERVICE_TOKEN` |
| 充值成功核销 | `POST /api/activation-codes/{id}/used` | Plus工具 | `LICENSE_SERVICE_TOKEN` |
| 失败转人工（不核销） | `POST /api/activation-codes/{id}/refund-review` | Plus工具 | `LICENSE_SERVICE_TOKEN` |

卡密状态机（两边一致）：`issued（已发放）→ redeeming（工具锁定）→ used（充值成功核销）`；失败 `refund_review`。**一张卡密最多一次成功扣款**（工具 v2.2 硬校验）。

## 3. 统一上线要部署的三块 + 一处配置

### 要部署
1. **Plus工具 licenseServer**（卡密库存）→ 建议 `license.aitokenapi.cc`（内网/仅胖虎后端可达即可）。启动设 `LICENSE_SERVICE_TOKEN` / `LICENSE_ADMIN_TOKEN`，`npm run start:license`（默认 3010）。
2. **Plus工具 买家端**（激活+自动化）→ 建议 `plus.aitokenapi.cc`。设 `ADMIN_API_KEY` / `CARD_POOL_SECRET` / 卡密来源=remote（指到 licenseServer + `LICENSE_SERVICE_TOKEN`）。
3. **panghu-admin**（AI订阅后台 + 商品管理页 + 客户端要读的商城接口）→ 复用现有 panghu-admin 容器，替换镜像。

### 一处配置（把两边接起来）
4. **panghu-admin 的 `.env` 追加**：
   - `PANGHU_LICENSE_SERVICE_BASE_URL = https://license.aitokenapi.cc`（或内网地址）
   - `PANGHU_LICENSE_ADMIN_TOKEN = <与 licenseServer 的 LICENSE_ADMIN_TOKEN 相同>`
   未配置时 panghu-admin 发卡密会"跳过推送"（开发用），配上后才真正写入库存。
5. **后台商品页设 GPT Plus 商品的 `plus_tool_url` = `https://plus.aitokenapi.cc`**（买家端地址）。客户端凭此打开 `?code=卡密`。

### 客户端
6. 客户端重新打包发布（含 AI订阅商城 + 接码内嵌 + 代理中心说明）。

## 4. 令牌口径（避免踩坑）

- **两个不同令牌**：`LICENSE_ADMIN_TOKEN`（胖虎后端写卡密用）与 `LICENSE_SERVICE_TOKEN`（Plus工具校验/核销用）。别混。
- 胖虎侧只需要 `LICENSE_ADMIN_TOKEN`（配进 `PANGHU_LICENSE_ADMIN_TOKEN`）。
- Plus工具买家端只需要 `LICENSE_SERVICE_TOKEN`（配进它后台"卡密来源→访问令牌"）。
- 「卡密」= 买家付费凭证；「扣款卡池」= 给 Stripe 付款的信用卡。两者完全不同，勿混。

## 5. 端到端实测清单（上线后按此走一遍）

1. 后台建一个 GPT Plus 代充商品（delivery=self_service_plus，plus_tool_url 填好），录几张测试卡密。
2. 后台确认 licenseServer 已收到这几张卡密（`GET /api/admin/activation-codes`）。
3. 客户端登录 → 增值业务 → AI订阅服务 → 买 GPT Plus（可选数量）→ 支付宝真实小额付款。
4. 付款成功 → 客户端弹卡密 + 「打开充值工具」→ 内置浏览器自动带 `?code=` 进入。
5. 在工具里输卡密（应校验通过、锁定）→ 提交一个真实 ChatGPT session → 自动化跑通 Plus 升级。
6. 成功后卡密核销为 used；再用同一张卡密应被拒（防刷）。
7. 失败/超时 → 转人工复核，卡密不误核销。

> ⚠️ 真实账号 Plus 自动化（第 5 步）首次大概率要微调页面选择器；真实支付宝付款、真实 Stripe 扣款卡都只有 panghu 本人能操作。
