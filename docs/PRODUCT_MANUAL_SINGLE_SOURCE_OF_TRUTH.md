# 胖虎AI多 Agent 一键部署工具唯一产品手册

最后更新：2026-06-26

## 1. 本手册的地位

本文件是“胖虎AI多 Agent 一键部署工具”的唯一产品级权威手册。

用途：

- 给 Codex / 子 Agent 做 UI、代码、文案、验收时的统一依据。
- 给后续维护窗口明确哪些信息以产品口径为准，哪些信息只属于技术维护或历史说明。

规则：

- 涉及产品结构、界面层级、客户可见文案、交付边界、验收标准时，以本手册为准。
- 涉及接口、构建、签名、打包、发布、脚本、目录和技术限制时，以 `docs/TECHNICAL_MAINTENANCE_MANUAL.md` 为准。
- `README.md` 只做仓库入口摘要，不再承担分散的产品定义职责。
- `legacy/` 目录下的旧文档只保留历史参考，不得作为当前产品判断依据。

## 2. 产品定位

本工具是客户侧桌面软件，不是脚本工具，也不是胖虎AI网站控制台的替代页。

它的职责是：

1. 让客户先统一登录胖虎AI账号。
2. 登录后按账号权益展示客户可使用的模块、Agent、服务和交付状态。
3. 在“配置Agent”模块内完成 API Key 创建/填写、环境检测、Agent 选择、安装、配置写入、启动检测、最小中文对话验收和功能验收矩阵。
4. 在“胖虎AI网站”模块内承载控制台、充值购买、API Key、推广返佣等网站能力的内置浏览器入口。
5. 在“增值业务”模块内展示服务端下发的可用业务入口、权益状态和交付状态。
6. 在“代理中心”模块内承载旧版代理中心迁移后的代理总览、工具代理后端和代理规则相关入口。

它不负责：

- 取代胖虎AI官网完整购买站。
- 把支付、钱包、控制台、后台管理逻辑整个搬进桌面端。
- 在本地硬编码注册、邀请码、商品价格、购买次数、返佣比例、套餐规则、设备数或有效期。
- 在登录前把买家模式和代理模式做成并列主入口。
- 在本地实现代理中心的商业规则。代理身份只来自登录后的账号权益，具体规则和数据由网站服务端与代理后端控制。

## 3. 当前产品边界

当前桌面端允许：

- 登录胖虎AI账号。
- 向服务端申请部署授权。
- 显示商业版账号、版本标识、剩余次数、有效期、设备数、公共域名。
- 根据服务端数据展示账号、权益、代理身份和交付摘要。
- 安装与配置四个 Agent：Codex、ClaudeCode（CC）、OpenClaw、Hermes。
- 用四 Agent 五维状态做交付跟踪：安装、启动、对话、验收、交付。
- 在登录后的内置浏览器中打开胖虎AI网站的控制台、推广返佣、创建 Key、充值购买、代理中心和增值业务入口。

当前桌面端不承诺：

- 在工具内完整复刻网页购买中心。
- 在未经过真实网页验收前，承诺注册、充值、支付、钱包管理、API Key 创建全流程已经闭环。
- 把未打通的 ClaudeCode、OpenClaw、Hermes 链路包装成已完整交付。
- 离线计算价格、购买次数、返佣、代理等级或课程权益。

当前内置浏览器口径：

- 桌面端可以在软件内 WebView 打开胖虎AI网站服务端页面。
- 控制台、推广返佣、创建 Key、充值购买、代理中心等业务仍由 `https://aitokenapi.cc` 服务端页面完成。
- 如果 `pywebview` 不可用或网页运行环境阻止嵌入，客户端必须明确提示回退浏览器，不能静默说已经完成内置闭环。
- 如果后续接入桌面内购买能力，仍必须走服务端控制，不得本地硬编码商品规则。

## 4. 固定产品结构

登录后的主界面结构必须长期固定为六块：

1. 顶部 TopBar
2. 顶部一级模块导航
3. 左侧当前模块子导航
4. 中间主工作区
5. 右侧账号 / 权益 / 交付状态面板
6. 底部 Execution Trace Log

顶部一级模块固定为：

1. 配置Agent
2. 胖虎AI网站
3. 增值业务
4. 代理中心

“代理中心”不是登录前模式入口，而是登录后的网站/后端代理业务入口，不能再退回旧的本地代理协助流程。

中间主工作区按模块切换：

- 配置Agent：显示单步骤卡片，一次只呈现当前子步骤。
- 胖虎AI网站：显示内置浏览器，打开胖虎AI网站的控制台、Key、充值、推广返佣等服务端页面。
- 增值业务：显示服务端下发的业务入口卡片、内置浏览器或占位状态。
- 代理中心：显示内置浏览器或代理后端入口，承接代理总览、工具代理后端和代理规则。

禁止回退成：

- 所有步骤堆成一整页
- 未登录时先展示完整主控制台
- 左侧固定 10 步向导替代一级模块导航
- 登录前买家模式 / 代理模式并列入口
- 右侧账号 / 权益 / 交付状态区消失
- 黑色运维终端式大顶栏
- 花哨装饰稿或玻璃拟态风格

## 5. 登录门禁规则

未登录前必须是“登录闸口”，不是主控制台。

未登录页允许显示：

- 品牌区
- 账号密码输入
- 最少说明
- 注册入口
- 打开胖虎AI网站注册页的入口

未登录页禁止显示：

- 买家模式 / 代理模式并列入口
- 左侧模块子导航
- 顶部一级模块导航
- 右侧账号、权益和 Agent 状态
- 完整部署控制台
- 完整执行日志

登录后的身份规则：

- 买家、代理、课程用户、增值业务用户都先走同一个胖虎AI账号登录。
- 代理不是登录前模式，代理身份是登录后账号权益的一部分。
- 代理身份是登录后权益，代理相关入口放在顶部“代理中心”模块内承接，不再作为登录前模式。
- 本地客户端不得自行判断、计算或写死代理返佣、代理等级、邀请奖励、价格或次数。
- 历史本地代理协助流程已废弃，不再作为客户可见入口、部署上下文或付费交付路径。

## 6. 视觉方向

唯一允许的主方向是：

- 中文界面
- 浅色企业级商业软件控制台
- 苹果风钛金白 / 浅色蓝色商业后台主色
- 低饱和灰白窗口背景
- 清晰边框和卡片层级
- 更像“客户交付软件控制台”，同时保留客服可解释的引导

不是以下风格：

- 黑色终端
- 概念稿大装饰条
- 玻璃拟态
- 强渐变
- 暖橙棕旧版客服向导
- 运维脚本面板
- 一页式营销页

## 7. 颜色与品牌

当前固定主色：

- 主色：`#0071E3`
- 背景：`#E8E8ED`
- 窗口面：`#F5F5F7`
- 侧栏：`#EBEBEC`
- 边框：`#D2D2D7`
- 成功绿：`#1A7F37`，用于通过、可继续
- 提示黄：`#B06000` / `#FFF7DF`，用于提醒、待确认

品牌规则：

- 窗口图标和品牌头像统一使用胖虎头像资产。
- 顶栏左上角优先使用胖虎头像，不再退回纯字母方块作为最终方案。
- 品牌区要安静，不能把过多技术信息塞到左上角。

## 8. 顶部 TopBar 规则

TopBar 必须承担：

- 品牌识别
- 产品名
- 当前账号
- 商业版本标识
- 剩余次数
- 检查更新入口

TopBar 不应该承担：

- 大段说明
- 复杂商业规则解释
- 一长串技术字段

视觉要求：

- 左右对齐稳定
- 不露头、不塌陷
- 普通窗口和全屏都保持同一中轴线
- 不要廉价拼贴感

## 9. 顶部一级模块导航规则

顶部一级模块导航必须放在 TopBar 下方或与 TopBar 稳定结合，承担产品主信息架构，不再使用旧的单一 10 步向导作为全局结构。

一级模块固定为：

1. 配置Agent
2. 胖虎AI网站
3. 增值业务
4. 代理中心

一级模块职责：

- 配置Agent：客户交付主链路，负责四 Agent 的安装、配置、验证和交付矩阵。
- 胖虎AI网站：承载注册、邀请码、创建 Key、充值购买、代理中心、账号中心等网站服务端页面。
- 增值业务：展示客户可购买或已开通的增值服务入口，具体规则来自服务端。
- 代理中心：承载代理总览、工具代理后端和代理规则等代理相关入口，具体规则来自服务端。

导航规则：

- 当前模块要有明确选中态。
- 模块切换时左侧子导航、中间工作区、右侧状态摘要要同步切换。
- 不允许把代理身份提前做成登录前入口。
- 不允许把网站里的购买、充值、邀请码、返佣规则复制到本地硬编码。

## 10. 左侧当前模块子导航规则

左侧只展示当前一级模块下的子导航，不再展示全局固定 10 步。

“配置Agent”模块的子导航建议为：

1. 创建或填写 API Key
2. 检测系统环境
3. 选择 Agent
4. 执行安装
5. 写入配置
6. 启动检测
7. 最小中文对话验收
8. 功能验收矩阵
9. 完成交付

“胖虎AI网站”模块的子导航建议为：

1. 控制台
2. 创建 API Key
3. 充值购买
4. 推广返佣

“增值业务”模块的子导航由服务端下发或显示预留分类，不在本地硬编码价格、次数或套餐规则。

“代理中心”模块的子导航建议为：

1. 代理总览
2. 工具代理后端
3. 代理规则

左侧导航职责：

- 只负责当前模块内定位和状态提示
- 不承担长说明
- 不替代顶部一级模块导航

## 11. 中间主工作区规则

中间区域必须根据当前模块显示单步骤卡片、内置浏览器或占位状态。

规则：

- 配置Agent模块一次只显示一个步骤卡片。
- 当前步骤标题要明确。
- 说明要口语但专业。
- 告诉客户“现在做什么、做完看哪里”。
- 不要把所有信息都堆在一页首屏
- 胖虎AI网站模块优先使用内置浏览器打开服务端页面。
- 增值业务和代理中心在内容未上线前可以显示清晰占位，但必须说明由服务端或网站接入。

必须走内置浏览器 / 网站服务端的事项：

- 注册账号
- 查看推广返佣 / 邀请入口
- 创建 API Key
- 充值购买
- 订阅、套餐、增值业务购买
- 代理中心、返佣、邀请奖励和代理权益查看

本地步骤卡不得写死这些事项的商业规则，只能提供入口、状态提示和客服可理解的引导。

## 12. 右侧账号 / 权益 / 交付状态面板规则

右侧必须长期固定承担“账号确认 + 权益摘要 + 交付结论”职责。

首屏优先级：

1. 当前账号和登录状态
2. 当前权益摘要
3. 当前交付结论
4. 四 Agent 五维状态
5. 当前模块相关状态

账号 / 权益摘要可以展示：

- 当前账号（脱敏）
- 商业版本标识
- 账号角色 / 权益标签
- 代理身份状态（如果服务端返回）
- 剩余次数或额度（如果服务端返回）
- 有效期
- 设备数
- 当前公共域名 `https://aitokenapi.cc`

右侧面板禁止：

- 本地计算商品价格
- 本地计算购买次数
- 本地计算返佣比例
- 本地计算代理等级
- 本地写死套餐权益
- 把未登录用户展示成已授权用户

四 Agent 固定为：

- Codex
- ClaudeCode（CC）
- OpenClaw
- Hermes

每个 Agent 状态必须拆成五个维度：

- 安装状态
- 启动状态
- 对话状态
- 验收状态
- 交付状态

禁止把五个维度合并成一个“总状态”替代展示。

## 13. 底部日志规则

底部日志区是 Execution Trace Log，不是主界面视觉核心。

规则：

- 登录后展示
- 未登录闸口不应抢主视觉
- 日志要可复制给客服
- API Key 不输出到日志

## 14. Codex 三种配置模式

Codex 的配置模式只讨论 Codex 自己的 `config.toml` 和 `auth.json`，不能把胖虎AI网站账号混进 Codex 登录。

胖虎AI账号的职责：

- 登录本工具。
- 登录胖虎AI网站。
- 获取服务端授权、权益、API Key、充值购买和代理中心信息。
- 不能登录 Codex。

Codex 当前固定支持三种模式：

1. 普通模式
2. 双态模式
3. 官方直登

普通模式：

- 默认给普通客户使用。
- Codex 走胖虎AI中转站 API。
- 客户填写胖虎AI API Key。
- 消耗胖虎AI中转站额度。
- 不需要登录 ChatGPT 账号。

双态模式：

- 只给需要保留 ChatGPT 登录态，同时仍消耗胖虎AI中转站额度的客户使用。
- 客户自己的 ChatGPT 账号只提供登录态。
- 模型请求仍走胖虎AI API Key。
- 消耗的是胖虎AI额度，不是 ChatGPT 账号额度。
- 本工具不代替客户登录 ChatGPT，不保存 ChatGPT 账号密码。

官方直登：

- 只给明确要使用自己 ChatGPT 账号额度的客户使用。
- Codex 走官方账号登录态。
- 不写入胖虎AI中转站 Key。
- 不消耗胖虎AI中转站额度。
- 如果客户本机没有 ChatGPT 登录态，必须在 Codex 内自行登录 ChatGPT 账号。

客户可见按钮口径：

- “一键部署（普通）”：安装所选 Agent，并写入胖虎AI普通 API 配置。
- “仅修复 Codex 配置”：不重装 Agent，只重新写入普通模式配置。
- “双态配置”：保留 ChatGPT 登录态，但模型消耗走胖虎AI API Key。
- “官方直登”：切换成使用客户自己的 ChatGPT 账号额度。
- “恢复最近备份”：配置异常时退回本次写入前状态。

所有 Codex 模式切换都必须提示：

```text
配置写完后，必须完全退出 Codex，再重新打开 Codex，新的配置才会生效。
```

产品层必须明确：模式切换会先保存当前 Codex 配置快照，再写入目标模式；历史登录态和客户配置不能因为切换模式被随意覆盖。

## 15. 审计与安全文案固定要求

界面和验收中必须明确表达：

- API Key 不输出到日志
- 不保存可恢复买家登录 token、部署 token 或第三方账号密码
- `profile.json` 只保存账号提示、API Key、模型和界面偏好
- 不保存可恢复买家登录 token，重启后必须重新登录胖虎AI账号
- 所有请求走公共域名 `https://aitokenapi.cc`
- 未通过功能验收矩阵不得包装成完整交付
- 注册、邀请码、创建 Key、充值购买、代理中心和返佣规则都走胖虎AI网站服务端
- 本地客户端不得硬编码价格、次数、返佣、套餐、有效期或设备数
- 胖虎AI账号不是 Codex 登录账号
- 普通模式和双态模式消耗胖虎AI中转站额度
- 官方直登消耗客户自己的 ChatGPT 账号额度
