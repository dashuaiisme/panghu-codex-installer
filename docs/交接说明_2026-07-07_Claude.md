### 2.2 「安装」与「写入配置」是两个独立步骤，别再合并
- 现在：**第4步「安装」= 只装软件**（后端 `start_install`/`_install_worker`，不写配置、不预占/扣次）；**第5步「写入配置」= 真写配置+验收**（按钮调 `start_deploy`）。
- 旧版把二者绑在 `start_deploy` 一把梭，且第5步只显示配置健康面板不写配置——**已修，别改回去**。
- **扣费时机没变**：仍在配置验收通过后（`_deploy_worker` 计费逻辑一行没动）。`_install_worker` 绝不能加预占/扣次逻辑。

### 2.3 支付方式：支付宝 WAP，别用旧 page.pay
- 工具订单走**手机网站支付**：`alipay.trade.wap.pay` / `QUICK_WAP_WAY`。服务端返回字段仍叫 `payment_url`，**不返回 qr_code**；客户端本地用 `qrcode`+`PIL` 把 `payment_url` 编码成二维码（`build_payment_qr_data_url`）。
- **别再按电脑网站支付 `alipay.trade.page.pay`(FAST_INSTANT_TRADE_PAY) 的旧数据来**（有 ¥50 单笔限额）。

### 2.4 通讯软件验收：服务端自动验收，客户端别提交内部字段
- 第10/11步：客户端只轮询 `acceptance_status`/`charged`，**不要**让买家手填 `source_event_id`/`inbound/outbound_platform_message_id`/`agent_response_digest`/`evidence_url`。这些由服务端从真实平台回调派生。

## 4. 已知坑 / 限制（别当 bug 反复"修")
1. **`build_config`/`merge_config` 忽略传入的 `model` 参数**，恒写死型号字符串（现为 `gpt-5.5`）。即买家在 UI 选别的型号也不会生效。本轮只把写死值改成 gpt-5.5；「按买家选择写型号」是**后续增强**（要把模板改成 f-string 用 `{model}`，并同步 `panghu_ai_client.py` 内联测试 `merge_config(...,"bad","bad")==expected` 那几处 + `test_agent_playbooks`）。
2. **撤单退款不自动退钱**：`reverse_tool_order` 只把订单置 `refund_pending` + 回收权益，**不调支付宝退款 API**。真退款要在支付宝商户后台手动做。
3. **`config validate`/`config check` 子命令**：客户端会跑 `openclaw config validate`、`hermes config check`（`panghu_ai_client.py:4236/4299`）。开发机上这两 CLI 是 TUI 型，非交互终端探测会启动它们的 Agent，子命令名是否被接受**待真交互终端确认**；若名字不符是**客户端可改项**。
