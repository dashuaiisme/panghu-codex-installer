## ✅ 已解决（原"唯一硬阻断"，2026-07-09 经授权上线；以下保留作背景与回滚参考）

**现象**：客户端「增值业务 → AI订阅服务」拉商品/下单/查单调用的是 `https://aitokenapi.cc/api/subscription/*`，但生产实测：

| 路径 | 实测 | 含义 |
|---|---|---|
| `GET /api/subscription/products` | **404**（newapi 格式错误体） | 落到主站 newapi，未转发 panghu-admin |
| `POST /api/subscription/orders` | **404** | 同上 |
| `GET /api/subscription/orders/{id}` | **404** | 同上 |
| `POST /api/deployer/orders`（对照，工具订单） | 405（panghu-admin 格式） | **已**正确路由到 8300 |

**根因**：2026-07-08 上线的 panghu-admin AI订阅后端（`subscription_routes.py`，镜像 `panghu-admin:20260708-2301-ai-subscription`）只加了后端代码+表+`/admin` 管理页，**没加对应的公网 nginx location**。hub 台账 2026-07-08 上线条也只记了后端与 `main.py 注册`，未记 nginx。Phase B（2026-07-05）加的 8 条买家 nginx location 早于订阅功能存在，只覆盖 `/api/deployer/*`。

**影响**：真实买家用客户端打开 AI订阅商城会一直 404 → Plus 充值链路在网络层不通。（客户端已优雅降级：显示"商品加载失败·重试加载"，不是白屏或假空。）

**代码层已证明端到端通（本地真实 HTTP）**：用客户端真实签发的 deployer token + 客户端自己的解析器（`parse_subscription_*`）打本地跑起来的 panghu-admin 订阅 API，7 项断言全过：未带 token→401 fail-closed、商品列表往返、自助下单即时 paid 且带 `plus_tool_url`、同幂等键复用同单、换幂等键→新单（复购可行，我的 nonce 修复与服务端 `(key,buyer)` 去重兼容）、订单状态往返、越权查单→404。服务端订阅测试 32 passed。**结论：客户端↔panghu-admin 的订阅代码链路完全通，`BuyerDep`=`require_buyer` 与已在生产工作的 `/api/deployer/*` 同一套 deployer-token 自校验（无需额外网关），所以修复就是下面这几条 nginx location。**

**已只读核对生产 nginx**（`/etc/nginx/sites-available/aitokenapi.cc`）：现有 `/api/deployer/*`、`/api/tool-orders/payment-status` 都是精确 `location =` → `127.0.0.1:8300`（6 个标准 proxy 头 + `X-Panghu-User "";`）；**全文无任何 `subscription` location** → `/api/subscription/*`（含主站的 `alipay/pay`）现在都落 newapi catch-all(3000)。因此加下面三块**精确/正则** location 后：订阅三路径转 8300，而 `/api/subscription/alipay/pay` 因不匹配任何一块、继续留在 newapi——**零碰撞**（nginx 精确 `=` 恒高于 catch-all，`orders/[^/]+` 正则也不匹配 `alipay/pay`）。

**精确修复（照抄现有 deployer 块的 6 头，插到那组 location 之后）**：

```nginx
    location = /api/subscription/products {
        proxy_pass http://127.0.0.1:8300;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Panghu-User "";
    }
    location = /api/subscription/orders {
        proxy_pass http://127.0.0.1:8300;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Panghu-User "";
    }
    location ~ ^/api/subscription/orders/[^/]+$ {
        proxy_pass http://127.0.0.1:8300;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Panghu-User "";
    }
```
